# C58 (on the C56 branch) · Misperceptions: refuse ties, confirm, set aside what doesn't fit

C57: with 1 of 5 pixels missing while learning, misreads became trusted "experiences" and made-up routes got through.
Runs (out-c58.txt), six held-back pairs as in C57:

| run | real routes (trusted) | made up | undecided |
|---|---|---|---|
| trust once (as C57) | 2 (2) | 0 | 4 |
| reading refuses ties | **5 (5)** | 0 | 1 |
| + set aside misfits | 5 (5) | 0 | 1 |
| + replay at rest | **6 (6)** | 0 | 0 |
| + trust only when lived twice | 6 (6) | 0 | 0 |

**Counting can't fix a systematic misperception.** The false step "junction → hill" had been lived 17 times: with a
pixel missing, the bridge fits the hill exactly as well as the bridge, every time. "Trust when lived twice" changed
nothing.

**Refusing ties when reading fixes it.** When two things explain a view equally well, reading now takes neither (the
completion rule's own tie rule, applied to reading too). 139 views were left "not sure" instead of guessed; the
experiences then hold gaps instead of false steps. Real routes: 2 to 5; with replay at rest, 6 of 6, all trusted, none
made up. This also settles the earlier disagreement between reading and completion in favour of one rule.

**Set aside misfits** (think again without a step that isn't trusted) never came into play here: nothing was left to
catch. **Replay at rest** gave the last gain (5 to 6).

**Still there:** 22 misreads that aren't ties remain, and some false steps among experiences (bridge → bridge etc.) didn't
cause wrong routes in this test. Refusing ties is an option in the branch (off by default, so every engine test is
identical); whether it should be the rule for reading everywhere needs the picture tests run with it on.
