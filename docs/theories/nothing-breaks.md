# Nothing breaks

> **Continued in [assemblies first](assemblies-first.md),** which makes assemblies the first-class citizens so that immutability holds without stale bonds filling memory, and brings deletion back only as a storage policy.

A theory note, from a second question-and-answer exchange between the owner and the assistant. **Nothing here has been
tested.** It records a pivot away from the project's founding premise. The premise was that heat frees bonds so that
structure can break and reconfigure, as in annealing metal. The conclusion here is that **bonds never break.** The
machine only forms new structure, and what stops being relevant is outcompeted and sinks to cold storage, still
connected but hard to reach.

This **supersedes §7–§9 of [how heat restructures](how-heat-restructures.md)** ("some breaking is needed", "breaking is
local, at the contact points", "breaking waits until one side has settled"). That note is kept as it was, as the record
of how the thinking got here. Related: [structure over strength](structure-over-strength.md), the
[language](../../language/README.md).

---

## 1. The question that started it

The last note left one thing open before breaking could be written in the language: what "settled" means. Breaking
was meant to wait until a contest was over, so that a true but harder-to-reach idea wasn't thrown away too early. But
what, in set terms, says the contest is over?

## 2. The first example didn't hold up

**The example as set up.** The machine knows "cat" well. Before it knows "cot", it reads nursery stories, reads
"c", something, "t" as "cat", and a bond forms from the nursery context to "cat". Later "cot" is learnt, and the two
contest in the nursery.

**The owner's answer.** This contradicts what was already agreed. In a nursery story there is nothing backing "cat",
so completion can't impose it. The heat stays, and "cot" forms as its own thing. No wrong bond forms, so there is
nothing to break.

**What that narrows.** If weak context never imposes, wrong structure can only form where context *did* back the wrong
reading: the crosstalk case, a cat and a baby both sleeping in a cot. That is the only kind of example where breaking
could ever be needed.

## 3. The question, sharpened

In that mixed scene, when "cot" is read as "cat", does the misreading leave any structure behind? If not, separating
"cot" from "cat" is only "cot" forming and gathering support until it wins, and nothing needs removing. If so, a wrong
bond sits there pulling towards "cat" even after "cot" is learnt, and separating them means breaking it.

The owner asked whether this was really the question of how competing things win out and how crosstalk gets
separated. It was, narrowed to: **does separating crosstalk ever need a bond broken, or is forming enough?**

## 4. The owner's answer: nothing breaks, mistakes become hard to reach

The owner challenged the premise of the project itself. Maybe no bonds break. The mistake ("cat" in the context of the
nursery) isn't reconfigured or forgotten. It becomes **harder to access** as the context around "cot" builds. With a
good enough memory you might remember once calling a cot a cat, but it fades, because the assemblies that now win are
the ones that become active. The wrong bonds are still there, but their assemblies never wake, because the more
correct ones have been built on top. A very particular cue could bring the mistake back. The more structure is built
around nurseries, the harder it is to reach.

**How it fits what was already there.**
- Abstraction was already forming rather than cutting: the shared part forms as a new assembly and nothing is split.
  With no breaking, the machine **only ever forms.**
- The owner's disk idea gives forgetting a home without breaking: a structure that never wins never gets warm, so it
  goes cold and moves out of memory. **Forgetting is going cold, not being broken.**
- If that holds, "settled" isn't needed. What's needed is "cold", which turns out to be easier.

## 5. The pushback: a lost structure still pushes

Competition is "most support wins, one more is enough". The old bond from the nursery context to "cat" is not silent:
each nursery scene still presses on "cat". Usually it is outvoted. But in a close contest it is exactly the extra
support that tips it, and the close contests are the mixed scenes, which is where the mistake came from. So the worry
was that the mistake keeps leaning on the hardest cases forever.

## 6. Gates have a limit, so new learning is new structure

**The owner's point.** If structure only ever builds, gates could grow without end, so they must have a limit: say
eight sources. When a gate is full and something has to change, either members are taken out of the gate, which gets
complicated, or a new assembly is formed. The owner prefers the second: it removes moving parts.

**What it buys.**
- A full gate can't take more, so **new learning has to become new structure**: a new assembly with its own gates.
  Members are never taken out of a gate. This is structure over strength again: more things, not fuller ones.
- This matches the "limited room" for bonds from the earlier sparse-bond experiments, and it keeps every gate check
  small and fast.
- The new assembly ("cot" in the nursery) outcompetes the old, again and again. The old isn't activated for a while,
  so it moves to disk.

The owner's picture is **a spectrum**. What is most relevant lives in memory, warm. What was wrong, and so is now
irrelevant, is largely forgotten: cold, on disk, even archived. But it is still connected somehow, just hard to reach.

## 7. Sparsity: pressed is not active

**The owner's correction.** Activity is sparse. Out of all the structure built around "cot" and the nursery, only the
most relevant gets selected, and as more structure comes in, what isn't relevant sinks further. "cat" doesn't make it
to the surface any more. The machine doesn't load everything associated with nurseries. It takes what is above the
threshold.

The owner then named the crux. If "cat" had been bonded to "baby", then whenever "baby" comes up it presses on "cat".
That happens every time.

**The distinction this needed.** Being **pressed** is not being **active**. With sparse activity, "cat" gets one press
from "baby", but in a scene full of cot-and-nursery structure it doesn't win a place. It is touched, never active. So if
"cold" means "not making it into the active set", sparsity does the job. In a genuinely mixed scene "cat" may still win
sometimes, which is fair, because that scene is ambiguous.

**Three levels, not two.** Pressed but not quite active is the warm layer from C92: primed alternatives just below
the threshold. So there is **active**, **primed** and **cold**, and the question became: does being primed keep
something in memory, or only being active? If priming counts, "cat" stays warm forever, because "baby" keeps priming
it.

## 8. What's in memory is decided by demand

**The owner's answer.** Look at how it would have to be built anyway. Members are streamed between memory and disk
according to how relevant they are to the context, and only the relevant members are pulled in. So there is a line
past which "cat" is no longer pulled in when nurseries come up, so it stops contributing, except under a very
specific cue. The line is drawn by **voting**: everything active in the nursery context votes for what it is bonded
to, and what is voted for is loaded. **It is based on demand.** Eventually "cat" isn't demanded any more.

**Why this answers the crux.** Loading by votes is a gate, the same kind of thing the machine already has, applied
to loading instead of firing. With the default bar of two, one stale bond from "baby" is one vote and can't load "cat"
on its own. Primed by a single thing is not enough to stay in memory.

**What it left.** Votes come from bonds, and the mistake's bonds don't go away. If the mistake was bonded to two or
three nursery things, it gets those votes in every nursery scene, however much "cot" builds up, because building
"cot" doesn't take votes away from "cat". With a fixed bar, "cat" would be loaded forever.

## 9. Ranking with limited room, and a floor

**The owner's answer.** Loading is a ranking: a competition for relevance. More relevant things rise and less relevant
things drop, with a cut-off. It is all temperature. And it combines both options: ranked, but with a fixed floor below
which something is so little demanded it has to go to disk regardless.

- **Ranking with limited room** decides what is in memory when space is contested. As "cot" and its context gather
  more votes, they fill the room and push "cat" out. **Things sink because something else is more wanted, not because
  their own votes dropped.** That is sparsity again, applied to memory itself.
- **The floor** clears out what is so little wanted it shouldn't take up room even when there is space.

**Keeping it binary.** "Relevance score" sounds like a number stored on each assembly, which would be strength coming
back. It needn't be stored. Relevance is worked out fresh at each moment as a count of the votes from what is active
now, the same count a gate does. Something stays in memory while it keeps getting enough votes now. It is pushed out
when something more wanted needs the room, or when its votes fall below the floor. No timer, no history, no stored
number: only counts in the moment, and one yes-or-no fact per assembly, whether it is in memory.

## 10. The decision

**Breaking is removed.** There is no reason for it yet. The language will not talk about bonds being reconfigured or
broken. Two kinds of change are left:

1. **Forming**: new structure is added, beside what's there.
2. **Moving between warm and cold**: decided by demand at each moment, ranked with limited room and a floor.

The contact point stops mattering for breaking. It may still be where heat is felt.

## 11. A ledger, not a rewrite

The owner noted that this reflects the nature of the project and how he likes to work. He keeps ledgers, like git
history. You can squash and rewrite, but a ledger keeps history immutable, and that is useful. The machine now does
the same: structure is only ever added, never erased. What changes is what is current: warm, in memory, winning.
Old structure is like old commits, still there, rarely visited, but reachable with the right cue.

## 12. What changes in the theory

- **Heat no longer frees bonds.** Heat still marks gaps, drives forming, and draws attention. It does not loosen or
  remove anything.
- **The cut is gone.** Abstraction is forming the shared part. Decomposition is forming the parts beside the whole.
- **Correction is outcompeting.** Being wrong is losing the ranking, not being erased. You forget the claim by no
  longer reaching it, not by deleting it.
- **Forgetting is a place, not an act.** Cold structure lives on disk, connected but hard to reach.
- **Gates are capped.** A full gate forces new structure.

## 13. The name

The machine is named after annealing: heat frees atoms so they can rearrange, then cooling sets them in a better
order. The central part of that picture, heat freeing bonds, is gone. Some of it still fits: heat marks where things
don't fit, and the system still settles towards lower energy. But the owner questions whether the name is right any
more. He has another, older name in mind for the language. This repository is a research repository rather than the
real thing, so the name stays here for now.

## 14. Costs and open questions

1. **Disk grows without end.** Nothing is removed, so cold storage only grows. Compression helps, but what bounds it, if
   anything, is open.
2. **Mistakes still vote in ambiguous scenes.** In a genuinely mixed scene the old wrong bond can still help "cat" win a
   place. The theory accepts that as fair, but it means some mistakes are never fully gone from the hardest cases.
3. **The ranking rule.** How much room memory has, how the ranking is done at each moment, and where the floor sits.
   These are trade-offs, probably declared settings.
4. **Reaching cold structure.** Votes come from what is active in memory. Whether cold structure can be voted back in
   from what's warm, and how cheaply, decides whether "hard to reach" is ever "reachable".
5. **The gate cap.** What size, and what happens exactly when a full gate's member needs to take part in something
   new: which new assembly forms, and around what.
6. **Tests.** Read "cot" as "cat" in mixed scenes, then build rich "cot" context. Does "cat" stop being loaded in
   nursery scenes with no bond removed? Does a specific cue still bring the old reading back? Does memory stay bounded
   while disk grows?
