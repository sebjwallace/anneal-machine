Segments, zoomed in: one cell, three memories

One cell that belongs to three assemblies: what goes wrong when its links are pooled, and how segments fix it. Drawn by hand to show the idea; not a run of the engine.

The cell's links

How to walk through it

The toggle keeps you on the same step, so flip it to compare. On step 1 with In one pool: one cell in the middle, with nine links from three groups (cells of A, C and F), all landing in a ring on the cell. Press Next: one cell from each group lights. The pool counts three, and the middle cell turns red: it has woken for a memory that isn't there. Press On segments: the same nine links now sit on three branches, each counting only one, so none fires and the cell stays quiet. Press Next again: two cells of A light. In both modes the cell wakes, in teal. With segments, A's branch says "2: fires", so you also know which memory woke it.

What it shows

A cell that belongs to several assemblies, zoomed in. With all its links in one pool, activity from different memories adds up and wakes it falsely. With its links sorted onto segments, one per memory, each segment counts only its own links: an AND of them. The cell wakes if any segment fires: an OR of its segments. Noise from several memories is never added together. The bigger picture, with columns of segmented cells, is in segments.

Where it comes from

The owner's dendritic-segments idea (C35), where pooling gave about 80% wrong recalls with five things stored; CTR-1 CON-9.
